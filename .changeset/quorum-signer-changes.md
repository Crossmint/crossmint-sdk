A recovery quorum can approve signer changes. `addSigner`, `removeSigner`, `addRecoveryMethod` and `removeRecoveryMethod` take a `signer` option, sent as the `approver`: a recovery quorum's locator, or one of the wallet's recovery methods. `useRecoveryMethod` accepts a key that is only a member of a recovery quorum; signer changes are then approved by that quorum. A change a quorum approves is created unsigned and returned as with `prepareOnly: true`, with its `transactionId` (or `signatureId`). The wallet's signers and recovery methods change only when it lands, and, as with `prepareOnly`, this client's `wallet.recoveryMethods` is not updated. Members sign it with `approve`, which signs the selected member's pending approvals; with no active key, the key selected with `useRecoveryMethod`, a recovery method or a quorum member, signs, and `approve` skips automatic device recovery for a member. `removeSigner`, `addRecoveryMethod` and `removeRecoveryMethod` then return `status` undefined; for `addSigner`, pass `prepareOnly: true` when a quorum may approve, so the return type matches. A wallet whose recovery methods are all quorums throws `RecoveryMethodRequiredError` until a member is selected or `signer` is passed. Device recovery resolves the recovery method that approves the new device signer before it creates the device key, so a wallet with several recovery methods and none selected throws `RecoveryMethodRequiredError` without leaving a key behind.
